# البدء باستخدام قالب رائد في سلة

يساعدك هذا الدليل على إعداد قالب رائد الأساسي لتعلّم تطوير قوالب سلة. تبقى أسماء الملفات والأوامر والمعرّفات التقنية بصيغتها الأصلية.

## 1. التعرّف على رائد

**Raed (رائد)** هو القالب الأساسي الرسمي لسلة. **Twilight** هو محرك قوالب سلة، و**Twig** هي لغة القوالب التي يستخدمها رائد.

إذا كنت مطوّرًا متمرسًا في Magento، فابدأ بدراسة طبقة عرض واجهة المتجر: التخطيطات، وقوالب الصفحات، والمكوّنات، وJavaScript، والتنسيقات، وإعدادات التاجر. تأتي بيانات المتجر وخدماته من منصة سلة. وتستخدم معاينة القالب متجرًا تجريبيًا في سلة.

المراجع:

- [مستودع رائد الرسمي وملف README](https://github.com/SallaApp/theme-raed)
- [دليل تطوير قوالب سلة](https://docs.salla.dev/421878m0)

## 2. حالة بيئة العمل عند كتابة الدليل

نتائج الفحص المسجلة بتاريخ 11 أكتوبر 2026:

| العنصر | نتيجة الفحص |
| --- | --- |
| مجلد العمل | `/workspace/themes` |
| المجلد المستهدف | `/workspace/themes/nura-raed`، وكان فارغًا |
| Node.js | `24.21.0` |
| npm | `11.19.0` |
| Salla CLI | `3.2.62` |
| Git | `2.43.0` |
| pnpm | لم يُعثر عليه ضمن PATH |

كان إصدار رائد في ملف `package.json` الرسمي الذي تم فحصه هو `1.358.0`. يفرض الملف استخدام pnpm عبر `preinstall`، ويحدد إصدار Node المطلوب بالنطاق `^22.18.0 || >=24.11.0`. إصدار Node في هذه البيئة يطابق هذا الشرط. تحقّق مجددًا من إصدار القالب في مستودعك المحلي بعد تنزيله.

المرجع: [ملف package.json الرسمي لرائد](https://github.com/SallaApp/theme-raed/blob/master/package.json).

## 4. إنشاء مستودع من قالب رائد

يتيح لك هذا المسار الحصول على الكود محليًا من مستودع تملكه ومربوط بحساب شركاء سلة.

1. افتح [SallaApp/theme-raed](https://github.com/SallaApp/theme-raed).
2. اختر **Use this template → Create a new repository**.
3. أنشئ مستودعًا باسم `nura-raed` في حساب GitHub الخاص بك.
4. سجّل الدخول إلى شركاء سلة وافتح **My Themes**.
5. اربط GitHub إذا لم يكن مربوطًا بالفعل.
6. اختر **Import Theme** ثم اختر مستودعك `nura-raed`.
7. أكمل بيانات القالب التي تطلبها البوابة.

تكتمل هذه الخطوة عندما يحتوي مستودعك على كود رائد ويظهر القالب في حساب شركاء سلة.

المراجع:

- [دليل إنشاء القالب: استخدام قالب رائد والاستيراد](https://docs.salla.dev/422775m0)
- [استيراد قالب موجود عبر البوابة](https://docs.salla.dev/421877m0)

## 5. استنساخ المستودع إلى المجلد المحلي

افتح الطرفية داخل الحاوية. استبدل `USERNAME` باسم مستخدم GitHub الخاص بك:

```bash
cd /workspace/themes/nura-raed
git clone https://github.com/USERNAME/nura-raed.git .
```

تعني النقطة `.` وضع الكود مباشرة في المجلد الحالي. يستخدم هذا الأمر المجلد الفارغ الذي أنشأته مسبقًا. إذا كان المجلد يحتوي على ملفات، افحصها أولًا؛ لا تحذفها لإجبار عملية الاستنساخ على النجاح.

إذا كان المستودع خاصًا، أكمل المصادقة مع GitHub باستخدام آلية مصادقة Git المتاحة في بيئتك.

تحقّق من النتيجة:

```bash
pwd
ls -la
cat package.json
```

تكتمل هذه الخطوة عندما تتوفر الملفات `README.md` و`package.json` و`twilight.json` ومجلد `src` في المجلد الرئيسي للقالب.

المرجع: [مسار التطوير: استنساخ مستودع القالب إلى البيئة المحلية](https://docs.salla.dev/421878m0).

## 6. تثبيت الاعتماديات

يستخدم إصدار رائد الرسمي الذي تم فحصه pnpm. إذا لم يكن pnpm متاحًا:

```bash
npm install -g pnpm
pnpm --version
```

ثم نفّذ ما يلي من المجلد الرئيسي للقالب:

```bash
cd /workspace/themes/nura-raed
pnpm install
```

يذكر دليل سلة العام الأمر `npm install`، لكن إصدار رائد الرسمي الذي تم فحصه يحتوي على السكربت `preinstall: npx only-allow pnpm`. اتبع ملف `package.json` وملف قفل الاعتماديات وتعليمات المستودع المحلي. إذا حددت نسختك إصدارًا معينًا لمدير الحزم، فاستخدم ذلك الإصدار.

تكتمل هذه الخطوة عندما ينجح تثبيت الاعتماديات دون أخطاء. إذا فشل، سجّل رسالة الخطأ وإصداري Node وpnpm قبل محاولة الإصلاح.

المراجع:

- [اعتماديات رائد ومدير الحزم ومتطلبات Node](https://github.com/SallaApp/theme-raed/blob/master/package.json)
- [ملف قفل pnpm في رائد](https://github.com/SallaApp/theme-raed/blob/master/pnpm-lock.yaml)

## 7. تسجيل الدخول وتشغيل المعاينة

كانت أداة Salla CLI مثبتة بالفعل في البيئة التي تم فحصها. نفّذ ما يلي من المجلد الرئيسي للقالب:

```bash
salla login
salla theme preview --with-editor
```

أكمل تسجيل الدخول في المتصفح واختر متجرًا تجريبيًا عندما يُطلب منك ذلك. يفتح الخيار `--with-editor` المعاينة مع محرر إعدادات القالب.

تراقب المعاينة تغييرات الملفات وتحدّث الصفحة المعروضة. اتبع الرابط والتعليمات التي تعرضها أداة CLI. عند استخدام حاوية تطوير، افتح الرابط في متصفح الجهاز المضيف وفقًا لتعليمات CLI؛ لا تفترض أن المعاينة تستخدم دائمًا المنفذ `3000` أو `5173`.

لعرض الخيارات المتاحة في إصدار CLI لديك:

```bash
salla theme preview --help
```

لإيقاف المعاينة، اضغط `Ctrl+C` في الطرفية التي تشغّلها.

تكتمل هذه الخطوة عندما يعرض المتجر التجريبي قالبك ويمكنك فتح محرر القالب. تتطلب المعاينة اتصالًا بالإنترنت وصلاحية الوصول إلى الحساب والمتجر التجريبي؛ نجاح البناء المحلي وحده لا يثبت نجاح المعاينة.

المرجع: [الدليل الرسمي لمعاينة القالب](https://docs.salla.dev/422776m0).

## 8. التحقّق من بناء نسخة الإنتاج

يستخدم الإصدار الرسمي الذي تم فحصه سكربت `production`:

```bash
pnpm run production
```

يشغّل هذا السكربت الأمر `webpack --mode production`. توجد أيضًا السكربتات `development` و`watch` والاسم البديل `prod`. افحص ملف `package.json` المحلي قبل استخدامها؛ لا تفترض وجود سكربت باسم `build` أو `dev`.

بناء نسخة الإنتاج لا ينشر القالب. تكتمل هذه الخطوة عندما ينتهي الأمر بنجاح دون أخطاء. ويبقى فحص واجهة المتجر عبر المعاينة ضروريًا.

المرجع: [سكربتات البناء في رائد](https://github.com/SallaApp/theme-raed/blob/master/package.json).

## 9. مسار بديل: إنشاء القالب عبر CLI

إلى جانب استخدام قالب GitHub والاستيراد عبر البوابة، توفر سلة إنشاء القوالب عبر CLI:

```bash
cd /workspace/themes
salla login
salla theme create --type twig --name nura-raed
```

الخياران `--type twig` و`--name` متاحان في إصدار Salla CLI `3.2.62` الذي تم فحصه. اتبع المطالبات، بما فيها تفويض GitHub وبيانات القالب. ولأن مجلد `nura-raed` موجود بالفعل، يسهل التحكم في مسار استخدام القالب والاستنساخ إلى المجلد الفارغ الموضح في الخطوتين 4 و5 في هذه البيئة. لا تستخدم المسارين لإنشاء القالب نفسه.

تحقّق من خيارات إصدار CLI لديك باستخدام:

```bash
salla theme create --help
```

## 10. البدء بقراءة الكود بعد الإعداد

اقرأ بالترتيب التالي، مع التأكد من وجود كل مسار في نسختك المحلية:

| الملف أو المجلد | ما تتعلّمه |
| --- | --- |
| `README.md` | تعليمات القالب الأساسي ومسار العمل |
| `package.json` | الاعتماديات ومتطلبات إصدار Node والسكربتات |
| `twilight.json` | البيانات الوصفية والميزات والإعدادات ومكوّنات التاجر |
| `webpack.config.js` | معالجة ملفات الواجهة وتكامل مراقبة التغييرات |
| `src/views/layouts/master.twig` | التخطيط المشترك وكتل الصفحات |
| `src/views/pages/index.twig` | نقطة الدخول للصفحة الرئيسية |
| `src/views/components/home/` | المكوّنات المستخدمة في الصفحة الرئيسية |
| `src/assets/` | JavaScript والتنسيقات والصور |
| `src/locales/` | النصوص المترجمة |
