# Firefox: Salla preview cannot load localhost assets

This guide covers the Salla CLI preview workflow tested with Firefox **157.0.1 (64-bit)** and a dev container.

## Symptoms

The preview has broken styling or missing functionality, and Firefox reports errors such as:

```text
Cross-Origin Request Blocked: http://localhost:8000/app.js
Reason: CORS request did not succeed. Status code: (null).

Firefox can't establish a connection to ws://localhost:8001/.
```

Opening `http://localhost:8000/app.css` directly may still work. Direct navigation does not prove that Firefox permits the Salla website to access local services.

Firefox includes Local Network Access restrictions. Mozilla documents a site-specific exception in its [personal device and local network permissions guide](https://support.mozilla.org/en-US/kb/control-personal-device-local-network-permissions-firefox).

## Before changing Firefox settings

- Keep the Salla preview command running in the dev-container terminal.
- In VS Code's **Ports** tab, confirm these exact forwarded addresses:

  | Container port | Forwarded address | Purpose |
  | --- | --- | --- |
  | 8000 | `localhost:8000` | Theme CSS, JavaScript, and images |
  | 8001 | `localhost:8001` | Live reload WebSocket |

- Open `http://localhost:8000/app.css` in Firefox. If it cannot load, resolve the server or port-forwarding problem first.

## Allow the Salla preview sites to access local services

Make this change in **Firefox on the computer where you view the preview**, not in the dev-container terminal.

1. Open `about:config` in Firefox and continue past its configuration notice.
2. Search for `network.lna.skip-domains`.
3. Record the current value so you can restore it later.
4. Edit the string value to include:

   ```text
   salla.design,s.salla.sa
   ```

   If it already contains entries, preserve them and append these domains with commas. Do not include `https://`, URL paths, or port numbers.

5. Save the value.
6. Keep the Salla terminal running and reopen the **complete preview link generated by the current CLI session**, including its localhost asset parameters.
7. Inside the editor, click its built-in **Preview** button to open the standalone theme preview.
8. Clear the Firefox Console and refresh that standalone preview.

This exception lets the two listed Salla sites bypass the local-network access check. Keep the exception limited to the sites needed for development. To undo it, restore the previous value or remove only these entries.

## Verify the result

- The standalone preview displays the correct theme and its identification text.
- Requests to `http://localhost:8000/app.js` and `product-card.js` no longer produce CORS errors.
- The connection to `ws://localhost:8001/` no longer fails.
- A local Twig text edit appears in the existing preview without a commit, push, or preview restart. Refresh once if necessary; needing a manual refresh means automatic page reload still needs checking.

In this troubleshooting session, the user confirmed that the standalone preview worked, the localhost CORS and WebSocket errors disappeared, and an uncommitted Twig text change appeared. The embedded editor view still had a separate rendering problem.

## Preview workflow and limitations

- Use the editor's **Preview** button. Manually opening its iframe in a new tab did not reliably retain the selected draft in this session.
- Keep the CLI preview/watch process running while editing. The verified active-session workflow supports uncommitted changes.
- Starting a new preview initializes it from a Git commit. Declining the CLI's commit prompt leaves existing uncommitted Twig/JSON changes out of that initial snapshot.
- Removing `assets_url` and `ws_port` from the editor URL can provide a hosted-assets workaround, but that does not verify local live reload. Keep the localhost parameters when testing the fix above.
- This setting does not repair unrelated errors such as a malformed font URL, a missing JavaScript import mapping, or HTTP 405 responses from Salla tracking endpoints. Diagnose remaining errors separately.
